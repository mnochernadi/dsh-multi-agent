# داشبورد چندعاملی DeepSeek Harness (dsh-multi-agent) 🤖⚡

> **داشبورد ارکستراسیون چندعاملی برای DeepSeek Harness (DSH)**  
> اجرای هماهنگ تیمی از agentهای هوش مصنوعی که در آن هر agent می‌تواند ارائه‌دهنده (Provider) و مدل زبانی کاملاً مستقلی داشته باشد، همراه با استریم زندهٔ رویدادها، چیدمان راست‌به‌چپ (RTL) و بدون نیاز به هیچ مرحلهٔ Build.

## 🌟 ویژگی‌های برجسته

- **🧩 چند-موتوره، نه فقط DeepSeek**: هر agent روی «موتور» انتخابی خودش اجرا می‌شود — DeepSeek Harness، Claude Code، Gemini CLI، Codex، Cursor Agent، OpenCode، Aider، Qwen Code، Goose — یا هر دستوری که خودتان تعریف کنید. برنامه‌های نصب‌شده خودکار تشخیص داده می‌شوند و همه‌چیز دستی قابل افزودن، ویرایش و بازنویسی است.
- **🎯 انتخاب مدل مستقل برای هر Agent**: می‌توانید برای Agent اصلی (Lead)، پژوهشگر (Researcher)، منتقد (Critic) یا نویسنده (Writer) مدل‌های کاملاً متفاوتی تعیین کنید (مثلاً DeepSeek-V3 برای برنامه‌ریزی و جمع‌بندی، Claude Haiku برای پیش‌نویس سریع، GPT-4o برای بازبینی منتقدانه).
- **🔌 اتصال مستقیم و بومی به DeepSeek Harness**: هر agent در قالب یک پروسهٔ مستقل `dsh --profile headless --json` اجرا می‌شود و تنظیمات مدل با استفاده از لایه‌های Cordis Patch به آن تزریق می‌شود.
- **🔐 استفادهٔ امن از اعتبارنامه‌های ذخیره‌شده**: کلیدهای API و ورودهای ثبت‌شده در اپلیکیشن دسکتاپ DSH بدون نیاز به افشای آن‌ها در مرورگر یا در فایل‌های پروژه مورد استفاده قرار می‌گیرند.
- **⚡ دو حالت ارکستراسیون پیشرفته**:
  - **خط لولهٔ داشبورد (Pipeline)**: Agent اصلی کار را برنامه‌ریزی کرده و به وظایف کوچک‌تر تبدیل می‌کند؛ سپس Sub-Agentها به‌صورت موازی یا ترتیبی (با رعایت وابستگی‌ها) اجرا شده و در نهایت خروجی توسط Agent اصلی تجمیع و بازنویسی می‌شود.
  - **حالت بومی (Native DSH)**: اجرای مستقیم تیم با استفاده از ابزار داخلی `subagent` خود دیپ‌سیک هارنس.
- **📡 استریم زنده با رویدادهای سرور (SSE)**: مشاهدهٔ گام‌به‌گام تفکر مدل (`thinking`)، پیام‌های متنی، فراخوانی ابزارها، زمان اجرا و مصرف توکن‌ها — مستقل از اینکه کدام موتور آن‌ها را تولید کرده است.
- **🩺 وضعیت صادقانهٔ موتورها**: «یافت نشد» / «نصب است ولی آزمایش نشده» / «آماده». اگر برنامه‌ای نصب باشد ولی وارد نشده باشد، پیام خطای خودش عیناً نمایش داده می‌شود (مثل `Not logged in · Please run /login`) و نه یک خطای مبهم.
- **🌍 دوزبانه با پشتیبانی کامل از زبان فارسی و راست‌به‌چپ (RTL)**: تغییر سریع بین فارسی و انگلیسی با یک کلیک.
- **📦 بدون وابستگی اجرایی و بدون Build**: استفاده از قابلیت مدرن Node.js در اجرای مستقیم فایل‌های TypeScript بدون نیاز به کامپایل یا باندلر (Webpack/Vite).

## 🧩 موتورهای اجرا (Engines)

«موتور» هر برنامه‌ای است که بتواند یک agent را تا پایان اجرا کند. داشبورد خروجی همهٔ موتورها را به یک واژگان رویداد یکسان تبدیل می‌کند؛ بنابراین خط لوله، تایم‌لاین و انتخاب‌های هر agent بدون توجه به برنامهٔ سازندهٔ رویدادها یکسان کار می‌کنند.

| موتور | نوع | رابط headless | وضعیت |
|---|---|---|---|
| `dsh` | DeepSeek Harness | `dsh --profile headless --json` + Cordis Patch تولیدشده | تأییدشده |
| `claude-code` | CLI | `claude -p --output-format stream-json --verbose` با متن از stdin | روی Claude Code 2.1.299 تأیید شد |
| `gemini-cli` | CLI | `gemini -p … --output-format stream-json` | بر اساس مستندات؛ با دکمهٔ «تست» تأیید کنید |
| `codex-cli` | CLI | `codex exec --json …` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `cursor-agent` | CLI | `cursor-agent -p …` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `opencode` | CLI | `opencode run …` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `aider` | CLI | `aider --message … --yes` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `qwen-code` | CLI | `qwen -p … --output-format json` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `goose` | CLI | `goose run -t …` | بر اساس مستندات؛ با «تست» تأیید کنید |
| `antigravity-ide` و `vscode` | IDE | ندارند — فقط برای «باز کردن پوشهٔ کاری» | تشخیص داده می‌شوند، ولی به‌عنوان agent اجرا نمی‌شوند |

### تشخیص خودکار

تشخیص سه‌حالته است، چون «فایل اجرایی وجود دارد» با «کار می‌کند» دو چیز متفاوت است:

| وضعیت | معنا |
|---|---|
| `missing` (یافت نشد) | هیچ‌کدام از نام‌ها یا الگوهای جست‌وجو پیدا نشد |
| `installed` (نصب است) | پیدا شد (همراه نسخه)، ولی هنوز اجرای موفقی نداشته است |
| `ready` (آماده) | تست سلامت واقعاً پاسخ گرفته است |

الگوهای جست‌وجو روی سیستم واقعی بسط داده می‌شوند (`%VAR%`، `$VAR` و `~`) و علامت `*` یک بخش از مسیر را تطبیق می‌دهد — به همین روش مسیرهای نسخه‌دار مثل `%LOCALAPPDATA%/Claude-3p/claude-code/*/*/claude.exe` پیدا می‌شوند. اگر چند نسخه موجود باشد، جدیدترین انتخاب می‌شود.

### افزودن یا ویرایش موتور

همه‌چیز از مسیر **تنظیمات ← موتورهای اجرا** قابل ویرایش است. هر فیلد به‌صورت «تفاوت» نسبت به پیش‌فرض داخلی ذخیره می‌شود، بنابراین بهبودهای بعدی پیش‌فرض‌ها هم به شما می‌رسد.

```jsonc
{
  "engine": {
    "id": "my-agent",
    "label": "My Agent",
    "kind": "cli",                       // cli | dsh | ide
    "enabled": true,
    "detect": {
      "commands": ["my-agent"],          // نام روی PATH یا مسیر کامل
      "searchGlobs": ["~/.my-agent/bin/my-agent"],
      "versionArgs": ["--version"]
    },
    "run": {
      "argsTemplate": ["-p", "{prompt}", "--model", "{model}"],
      "outputFormat": "json-lines",      // dsh-json | claude-stream-json | gemini-stream-json | json-lines | text
      "promptViaStdin": false,
      "extraArgs": ["--yes"]
    }
  }
}
```

جای‌نگهدارهای قالب: `{prompt}`، `{model}`، `{cwd}`، `{sessionId}` و `{extra}`. اگر مقدار یک جای‌نگهدار خالی باشد، هم خودش و هم سوییچ قبل از آن حذف می‌شوند؛ بنابراین `["--model", "{model}"]` بدون انتخاب مدل هیچ آرگومانی تولید نمی‌کند. جای‌نگهدارهای ناشناخته عمداً دست‌نخورده می‌مانند تا اشتباه تایپی در قالب دست‌ساز در خط فرمان دیده شود و بی‌صدا حذف نشود.

اگر برنامه پشتیبانی می‌کند، `promptViaStdin: true` را ترجیح دهید: متن وظیفه می‌تواند طولانی باشد و خط فرمان ویندوز محدودیت سختی دارد.

### API موتورها

| متد | مسیر | کاربرد |
|---|---|---|
| `GET` | `/api/engines` | فهرست همهٔ موتورها با وضعیت تشخیص زنده |
| `PUT` | `/api/engines` | افزودن یا ویرایش یک موتور |
| `GET` | `/api/engines/:id` | یک موتور، با تشخیص مجدد |
| `DELETE` | `/api/engines/:id` | حذف موتور دلخواه، یا پنهان‌کردن پیش‌فرض داخلی |
| `POST` | `/api/engines/:id/detect` | اسکن مجدد برای یافتن فایل اجرایی |
| `POST` | `/api/engines/:id/test` | اجرای تست سلامت (یک فراخوانی واقعی و بسیار کوچک) |
| `POST` | `/api/engines/:id/handoff` | باز کردن پوشهٔ کاری در موتورهای IDE |

## 🚀 راه‌اندازی سریع

### پیش‌نیازها
- **Node.js**: نسخهٔ `22.18.0` یا بالاتر (نسخهٔ `24.x` پیشنهاد می‌شود).
- **DeepSeek Harness (DSH)**: برنامهٔ دسکتاپ بر روی ویندوز، لینوکس یا مک نصب باشد.

### نصب و اجرا

```bash
git clone https://github.com/mnochernadi/dsh-multi-agent.git
cd dsh-multi-agent
npm start
```

سپس مرورگر خود را در آدرس **`http://127.0.0.1:7317`** باز کنید.

## 🔍 بررسی وضعیت و عیب‌یابی محیط (`npm run probe`)

برای اطمینان از شناسایی فایل اجرایی DSH و بررسی Providerها و Modelهای پیکربندی‌شده:

```bash
npm run probe
```

همچنین می‌توانید صحت ترکیب یک مدل خاص را بدون مصرف توکن تست کنید:
```bash
npm run probe -- --provider omni --model deepseek-v4.1-flash:free --effort max
```

## ⚙️ پیکربندی

فایل `.env.example` را به `.env` کپی کرده و در صورت نیاز مقادیر را تغییر دهید:

```ini
# آدرس و درگاه سرور
DSH_MA_DASHBOARD_HOST=127.0.0.1
DSH_MA_DASHBOARD_PORT=7317

# مسیر dsh (در صورت خالی بودن خودکار شناسایی می‌شود)
DSH_MA_DSH_BIN=
DSH_MA_DSH_HOME=

# حداکثر تعداد اجرای همزمان agentها
DSH_MA_MAX_CONCURRENCY=4

# استفاده از اعتبارنامه‌های ذخیره‌شدهٔ برنامهٔ DSH
DSH_MA_TRUST_STORED_CREDENTIALS=true

# زبان پیش‌فرض (fa یا en)
DSH_MA_LANGUAGE=fa
```

همچنین تمامی این مقادیر از طریق بخش **تنظیمات** در رابط کاربری داشبورد نیز قابل ویرایش هستند.
